# Development instructions

Small Sites Worker app, no npm dependencies. Preserve workbook defaults and the user-approved organizer extensions below; no generic Swiss library or additional formats.

- Domain: `src/domain.mjs`. Raw score integers are hundredths; default divisor 100 matches workbook points/pairing exactly. User-approved custom divisor is an integer 1–10000; compare cumulative rational points through common integer numerators, never rounded display values. Complete 3/4-player games, three Swiss rounds, manual finals. Explicit amendRoster supports late additions/withdrawal/return, preserving played games and IDs; apply to unplayed current games or future rounds. Saved group changes clear affected games only; historical score/group/divisor changes explicitly discard dependent rounds/finals with audit snapshots. Never silently regenerate.
- Access: `src/access.mjs`. Account-free, per-tournament high-entropy management key plus Secure/HttpOnly/SameSite=Strict browser cookie. Store only hashes. Every existing-tournament write, deletion, backup, restore and key replacement requires its owner-session binding. A different tournament's owner, arbitrary identity header or URL knowledge is insufficient. No email allowlist, first-visitor claim or shared Site token.
- Recovery: management key in a URL fragment, immediately cleaned. No exchange until explicit confirmation; no key consumption on GET/link preview. Private keys are transient module memory only. Never log, screenshot, forward, store in source/JS storage, or include them in public records/history/backups. A replacement key revokes other sessions for that tournament only.
- Public routes: one tournament URL, no public directory. Strict result projection omits venue/private notes, audit, seeds, revision/archive metadata and all credentials. Legacy rows with null management hash stay untouched, hidden and unclaimable. Archived results are hidden from spectators.
- Deletion: owner-only POST `/api/tournaments/:id/delete`, explicit confirmation and revision CAS. Remove grants and the tournament in one conditional D1 batch; preserve both if stale or failed. Never delete real records during QA; clean up only synthetic IDs created by that run. No recovery/backup restore after permanent removal.
- Persistence/API: `src/worker.mjs`, D1 `DB`. Conditional UPDATE revisions and atomic batches. Schema-only migrations in `drizzle/`; applied migrations immutable. No production request-time schema changes. The nullable ownership migration does not assign old records.
- UI: `public/`. Russian text, escaped data, semantic light/dark/system tokens, persistent preference before first paint. Tab-scoped drafts are explicitly unsaved, never authoritative. Keep focus, inline errors, keyboard entry, Cancel/Back and mobile behavior. Owner settings hold backup/history; main navigation stays simple. Export UTF-8 CSV and tab-separated results for Google Sheets; prevent formula injection.
- `npm run build`, `npm test`, `npm run dev`. Rebuild before local browser QA because assets are embedded. Optional local-only `scripts/ui-regression.mjs`, `scripts/ui-ownership.mjs` use PLAYWRIGHT_MODULE/CHROMIUM_PATH. They must redact all ephemeral capability/cookie values from errors and never use Site service credentials.
- Development adapter uses Node SQLite and a separate non-Secure cookie only on loopback. Production uses the `__Host-` Secure cookie. Tests must verify production cookie attributes and direct API denials.
- Preserve `.openai/hosting.json` Site ID, data and requested audience. User approved public spectator access, after server authorization tests. Do not expose private backups/documents as public artifacts. Do not mint/rotate service/source credentials without required chat approval.
- Exclude dist, local databases/state, credentials, original XLSM and extracted VBA from Git. Never execute workbook macros. Keep independent-code attribution and official unmodified PolyForm license/NOTICE.

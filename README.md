# Своя игра · Турнир

Опубликованное приложение: https://svoyak.fittoast513.chatgpt.site

Русскоязычное приложение для турниров по нестрогой швейцарской системе из книги Дениса Галиакберова «Табличка СИ DG.xlsm»: три круга, бои по 3–4 игрока, грандфинал и малый финал. Правила реализованы независимо; исходная книга и VBA не распространяются и не исполняются. Подробности: [анализ книги](docs/WORKBOOK_ANALYSIS.md).

## Для организатора и зрителей

1. Создайте турнир без регистрации. Этот браузер получает защищённую сессию управления.
2. Сохраните **ссылку для организатора** в личном сообщении или другом закрытом месте. Она восстанавливает доступ после очистки cookies или на другом устройстве. Любой обладатель этой ссылки может редактировать именно этот турнир.
3. Найдите участников по имени в справочнике, выберите сразу нескольких или введите нового игрока вручную. Добавьте уникальные имена игроков и проведите первый круг. Допустимо 3, 4 или 6–40 игроков; 5 нельзя разбить на бои по 3–4 человека.
4. Внесите весь счёт боя. Enter переходит к следующему полю, Ctrl/Cmd+Enter сохраняет бой. Предпросмотр мест/очков помечен; таблица учитывает только сохранённые результаты.
5. После завершения всех боёв проведите следующий круг. После третьего круга вручную выберите состав финалов и введите счёт и места.
6. Отправьте участникам **ссылку для просмотра**. Она показывает только результаты без права редактирования, не требует аккаунта и не открывает список чужих турниров.
7. В «Результаты → Экспорт» скопируйте сыгранные бои для рейтинга в Google Таблицы либо скачайте итоговую таблицу в UTF-8 CSV с BOM и разделителем `;`. Формулоподобные имена экранируются. Автоматической связи с Google и дополнительных аккаунтов нет.

Основные экраны: Игроки, Бои, Результаты; финалы находятся рядом с кругами. Обе ссылки находятся рядом с названием турнира; обмен игроков — рядом с боями до первого результата. Остальные действия находятся в меню «Ещё». Демо-турниров в обычном интерфейсе нет. Дата нового турнира — сегодняшняя дата браузера, с возможностью изменить её. Рядом с началом первого круга заранее показано, сколько боёв будет по 3 и по 4 игрока; при неподходящем составе действие отключено. История, полная резервная копия, восстановление и отмена кругов находятся в настройках владельца. Перезапись результата требует подтверждения; для изменения старого результата нужно явно отменить последующие круги/финалы. Журнал сохраняет отменённые данные. Архив скрывает результаты от зрителей, сохраняя их владельцу. Красный × на карточке турнира и в настройках владельца удаляет турнир с сервера навсегда после короткого подтверждения, без ввода названия. Все его ссылки перестают работать; восстановить копию после удаления исходной записи нельзя.

## Справочник и рейтинг в Google Таблицах

В приложение скопированы только 58 канонических имён из [Rating!A3:A60](https://docs.google.com/spreadsheets/d/1wBs75fAb7MPoHXUC6bbTRgz_siL_8JiW-EOzgos2ZyU/edit#gid=0&range=A3:A60). Это снимок справочника, без автоматической синхронизации. В этой книге нет постоянных ID: связи построены по точным именам, поэтому выбранные имена сохраняются без переименования. Новых игроков можно добавить вручную.

«Скопировать для рейтинга» выдаёт только A:D листа [Data](https://docs.google.com/spreadsheets/d/1wBs75fAb7MPoHXUC6bbTRgz_siL_8JiW-EOzgos2ZyU/edit#gid=220213350): шесть строк на сыгранный бой (заголовок, четыре места, пустая строка), дата в A, номер места в B, имя в C и исходный счёт в D. Для трёх игроков четвёртое место пустое. Идут круги по порядку, затем ГФ/МФ; незавершённые бои пропускаются, нулевой и отрицательный счёт сохраняется числом.

Вставляйте **только значения** в первый свободный блок A:D. Не затрагивайте E:AK; формулы должны быть протянуты на добавленные блоки. Повторная вставка удвоит результаты, а события одной даты агрегируются вместе. Приложение не вычисляет и не изменяет рейтинговые формулы, исторические записи или лист Packs. Итоговая CSV-таблица — отдельный читаемый отчёт, не замена исходным счетам Data.

## Доступ без аккаунтов

`src/access.mjs` выдаёт случайные 256-битные секреты. Основной cookie — `__Host-svoyak-owner`, Secure, HttpOnly, SameSite=Strict, Path=/, срок до года. На сервере хранятся только хеши сессий и отдельного ключа управления каждого турнира. Таблица `tournament_owner_sessions` связывает конкретный браузер только с теми турнирами, которыми он вправе управлять. Знание публичного ID/URL, подмена полей владельца или наличие доступа к другому турниру не дают прав на изменение.

Приватная ссылка использует фрагмент `#manage=…`, который не передаётся в HTTP URL или Referer. Приложение немедленно убирает его из адресной строки и просит явное подтверждение перед обменом на HttpOnly cookie. Предпросмотр ссылки не выполняет обмен и не расходует ключ. После перезагрузки сам ключ не хранится в JavaScript-хранилищах; управление продолжает работать через cookie. Если нужно заново сохранить утраченную ссылку, владелец может явно создать новую: прежний ключ и доступ других браузеров к этому турниру будут отозваны.

Публичный ответ содержит только название и дату турнира, имена игроков, бои/счёт, финальные места и производную таблицу. В нём нет места проведения/заметок, истории, случайных seed, внутренних ревизий, cookie, хешей или полных резервных копий. Списка всех публичных турниров нет: `/api/tournaments` показывает только турниры текущего браузера. Общая документация требует действующей сессии управления; LICENSE/NOTICE и безопасные UI/домен-ресурсы доступны публично.

Резервная копия не содержит ключей и не переносит права управления. Восстановление создаёт отдельный турнир с новым приватным ключом и разрешено только браузеру, уже управляющему исходным турниром. Для другого устройства сначала откройте сохранённую приватную ссылку. Если исходной записи больше нет или потеряны и cookies, и приватная ссылка, автоматического восстановления прав нет.

Старые записи, созданные до введения владения, сохраняются с пустым хешем и не могут быть присвоены первым посетителем. Они не публикуются и не редактируются без отдельного проверенного решения о переносе. При проверке живой базы перед этой версией такими записями были только три архивных синтетических QA-турнира.

## Локальный запуск

Node.js 22.13+ (рекомендуется 24), Git и современный браузер. Установка npm-зависимостей не требуется.

```sh
npm run build
npm test
npm run dev
```

Откройте напечатанный loopback URL. `.local/tournaments.db` содержит локальную SQLite-базу; каталог исключён из Git. Сохраните его для продолжения после перезапуска. В локальном HTTP-адаптере используется отдельный HttpOnly cookie `svoyak-dev-owner` без Secure; production Worker всегда использует защищённый `__Host-` cookie. Данных/сессий между локальной и опубликованной базой нет.

## Архитектура и размещение

Sites использует Cloudflare Workers и D1 (SQLite), поэтому предпочтённый в исходном задании .NET/Blazor заменён на небольшое приложение из ES-модулей без npm-зависимостей. `src/domain.mjs` содержит неизменённые правила; `src/access.mjs` — права конкретного турнира; `src/worker.mjs` — API/сохранение; `public/` — интерфейс. Сборка встраивает UI и документацию в один Worker. Исходная миграция `0000_tournaments.sql` неизменна; `0001_tournament_ownership.sql` добавляет nullable-хеш и таблицу сессий без автоматической передачи старых записей.

Все записи ревизии выполняются условным UPDATE; создание/выдача прав и замена ключа — транзакционным D1 batch. Схема создаётся только миграциями, не в production-запросах. Проверяются источник JSON-запросов и права каждого изменения/backup/restore/rollback. Секреты не попадают в публичный JSON, журнал или резервные копии. В коде/браузере нет общего административного токена Sites.

В этой среде отсутствовали документированные Sites bootstrap/source helper executables и исходники Vinext starter. Используются совместимый автономный Worker-артефакт и обычный аутентифицированный Git. `.openai/hosting.json` сохраняет идентичность Site и D1 binding `DB`. Публичный доступ допускается только после проверки серверных ограничений. Новые или заменённые служебные credentials требуют отдельного разрешения, когда это ограничение задано в чате.

## Темы, сохранение и проверки

В верхней панели доступны **Как в системе**, **Светлая**, **Тёмная**; выбор сохраняется и применяется до первого показа страницы. Темы охватывают таблицы, окна, поля и ошибки; печать всегда светлая. URL сохраняет экран/круг, поддерживается Back/Cancel. Настройки темы и активного турнира — локальные предпочтения. Несохранённый ввод счёта/настроек хранится отдельно в sessionStorage этой вкладки, помечен как черновик и никогда не считается сохранённым результатом.

`npm test` проверяет формулы, все допустимые количества игроков, три многораундовых эталона (12/16/24 игрока), исправления/отмену, финалы, SQLite-перезапуск, ревизии и безопасность владения. Необязательные браузерные проверки при установленном Playwright:

```sh
PLAYWRIGHT_MODULE=<module-path> CHROMIUM_PATH=<browser-path> node scripts/ui-regression.mjs
PLAYWRIGHT_MODULE=<module-path> CHROMIUM_PATH=<browser-path> node scripts/ui-ownership.mjs
PLAYWRIGHT_MODULE=<module-path> CHROMIUM_PATH=<browser-path> node scripts/ui-sheet-flow.mjs
PLAYWRIGHT_MODULE=<module-path> CHROMIUM_PATH=<browser-path> node scripts/ui-group-preview.mjs
PLAYWRIGHT_MODULE=<module-path> CHROMIUM_PATH=<browser-path> node scripts/ui-open-controls.mjs
```

Эти скрипты разрешают только loopback, используют вымышленные данные и не используют служебные токены Sites. Проверяются полный турнир, экспорт, темы/контраст, мобильный вид, повторные действия, Cancel/Back, прерванный ввод и восстановление владения. Отчёт: [VERIFICATION](docs/VERIFICATION.md).

## Правила и ограничения

Очки за бой = `4 − среднее место + счёт / 100`. Счёт хранится в целых сотых, очки — в десятитысячных, расстояния — в миллионных. При ничьей место усредняется. Жеребьёвка 2/3 круга минимизирует сумму расстояний с конечными штрафами 1000/2000 за предыдущие встречи и поправкой номера регистрации; это не запрет повторов и не обычная библиотечная Swiss-парность. Первый круг случаен, seed сохранён.

Excel/VBA не исполнялись: эталоны — независимый перевод идентифицированных формул с точной рациональной арифметикой. Отличия: другой генератор случайной первой жеребьёвки, максимум два знака счёта, атомарный полный бой и строгая проверка переходов/исправлений. Автоматические пропуски, снятия после старта, квалификация финалистов и иные форматы исходной книгой не определены и не добавлены.

# Своя игра · Турнир

Опубликованное приложение: https://svoyak.fittoast513.chatgpt.site

Русскоязычное приложение для турниров по нестрогой швейцарской системе из книги Дениса Галиакберова «Табличка СИ DG.xlsm»: три круга с боями по 3–4 игрока, грандфинал и необязательный малый финал с гибким числом участников. Правила реализованы независимо; исходная книга и VBA не распространяются и не исполняются. Подробности: [анализ книги](docs/WORKBOOK_ANALYSIS.md).

## Для организатора и зрителей

1. Создайте турнир без регистрации. Этот браузер получает защищённую сессию управления.
2. Сохраните **ссылку для организатора** в личном сообщении или другом закрытом месте. Она восстанавливает доступ после очистки cookies или на другом устройстве. Любой обладатель этой ссылки может редактировать именно этот турнир.
3. Найдите участников по имени в справочнике, выберите сразу нескольких или введите нового игрока вручную. Добавьте уникальные имена игроков и проведите первый круг. Допустимо 3, 4 или 6–40 игроков; 5 нельзя разбить на бои по 3–4 человека.
4. Внесите весь счёт боя. Enter переходит к следующему полю, Ctrl/Cmd+Enter сохраняет бой. Предпросмотр мест/очков помечен; таблица учитывает только сохранённые результаты.
5. После завершения всех боёв проведите следующий круг. После третьего круга вручную выберите состав финалов и введите счёт; места рассчитаются автоматически.
6. Отправьте участникам **ссылку для просмотра**. Она показывает только результаты без права редактирования, не требует аккаунта и не открывает список чужих турниров.
7. В «Результаты → Экспорт» скопируйте сыгранные бои для рейтинга в Google Таблицы либо скачайте итоговую таблицу в UTF-8 CSV с BOM и разделителем `;`. Формулоподобные имена экранируются. Автоматической связи с Google и дополнительных аккаунтов нет.

Основные экраны: Игроки, Бои, Результаты; финалы находятся рядом с кругами. Обе ссылки находятся рядом с названием турнира; обмен игроков — рядом с боями, в том числе после записи результата. Рядом с вкладками турнира находятся «Настройки» (только владельцу) и «Экспорт» с печатью (всем просматривающим). История изменений открывается из настроек этого турнира. В верхнем меню «Ещё» остаются только создание нового турнира и общая помощь; тема — общая настройка приложения. Добавление списком находится на экране игроков, загрузка файла — в его диалоге. Демо-турниров в обычном интерфейсе нет. Дата нового турнира — сегодняшняя дата браузера, с возможностью изменить её. Рядом с началом первого круга заранее показано, сколько боёв будет по 3 и по 4 игрока; при неподходящем составе действие отключено. История, полная резервная копия, восстановление и отмена кругов находятся в настройках владельца. Перезапись результата требует подтверждения; при изменении старого результата окно заранее показывает отменяемые следующие круги/финалы. Журнал сохраняет отменённые данные. Архив скрывает результаты от зрителей, сохраняя их владельцу. Красный × на карточке турнира и в настройках владельца удаляет турнир с сервера навсегда после короткого подтверждения, без ввода названия. Все его ссылки перестают работать; восстановить копию после удаления исходной записи нельзя.

Если во время подтверждения другой организатор изменил турнир, сохранение в старом окне отключается. Закройте его, проверьте обновлённый состав и откройте действие заново. Несохранённый счёт очищается только для боёв с изменившимся порядком игроков. При временной ошибке без изменения турнира можно повторить сохранение в том же окне.

## Картинки для Telegram

Кнопка «Картинка» находится у кругов, финалов и на экране результатов; она также доступна из экспорта. Выберите завершённый этап, проверьте предпросмотр и нажмите «Копировать картинку», затем вставьте в Telegram. Если браузер не разрешает копировать PNG, скачайте его. После круга картинка содержит счета боёв и швейцарскую таблицу именно на тот момент; после финалов — итоговые места и отдельную швейцарскую таблицу. Большие таблицы делятся на несколько изображений без пропуска игроков. В «Текстовая версия» есть «Копировать текст»: тот же сохранённый этап копируется единым форматированным блоком для Telegram. Длинные результаты делятся на пронумерованные сообщения до 3900 символов без обрезки игроков. При ограничениях браузера доступен обычный текст или выделение для ручного копирования. Изображения создаются в браузере из сохранённых результатов, не содержат приватных данных и доступны по ссылке для просмотра. Несохранённый ввод не включается. На экране результатов переключатель отделяет итоговые места от швейцарских; финальное место больше не смешивается с швейцарским рангом.

## Справочник и рейтинг в Google Таблицах

В приложение скопированы только 58 канонических имён из [Rating!A3:A60](https://docs.google.com/spreadsheets/d/1wBs75fAb7MPoHXUC6bbTRgz_siL_8JiW-EOzgos2ZyU/edit#gid=0&range=A3:A60). Это снимок справочника, без автоматической синхронизации. В этой книге нет постоянных ID: связи построены по точным именам, поэтому выбранные имена сохраняются без переименования. Новых игроков можно добавить вручную.

«Скопировать для рейтинга» выдаёт только A:D листа [Data](https://docs.google.com/spreadsheets/d/1wBs75fAb7MPoHXUC6bbTRgz_siL_8JiW-EOzgos2ZyU/edit#gid=220213350): шесть строк на сыгранный бой (заголовок, четыре места, пустая строка), дата в A, номер места в B, имя в C и исходный счёт в D. Для трёх игроков четвёртое место пустое. Идут круги по порядку, затем ГФ/МФ; незавершённые бои пропускаются, нулевой и отрицательный счёт сохраняется числом.

Вставляйте **только значения** в первый свободный блок A:D. Не затрагивайте E:AK; формулы должны быть протянуты на добавленные блоки. Повторная вставка удвоит результаты, а события одной даты агрегируются вместе. Приложение не вычисляет и не изменяет рейтинговые формулы, исторические записи или лист Packs. Итоговая CSV-таблица — отдельный читаемый отчёт, не замена исходным счетам Data.

## Пять игроков и стулья

При пяти участниках каждый круг по умолчанию делится на3+2. В меньший бой можно добавить «стул»: нажмите «Добавить стул» на карточке. Это отдельное пустое место без имени участника, ввода счёта, ранга и очков. Убрать его можно крестиком в строке. Стул не влияет на отрицательные результаты, жеребьёвку, число участников или пропуски. Число реальных игроков и стульев в одном бою — не больше40.

Стулья сохраняются на сервере, в резервной копии и при повторной жеребьёвке того же боя. Они видны по ссылке для просмотра и в печати. В рейтинговом Data остаются обычные пустые неиспользованные строки; в полном CSV сыгранных боёв стул представлен отдельной строкой со статусом и пустым счётом. Если при перераспределении несыгранных боёв удаляется бой со стульями, окно предупреждает об этом; данные сохраняются в истории. Изменение пустых мест не сбрасывает сыгранные результаты и следующие круги.

## Несыгранные бои и вынужденные пропуски

Карандаш на несыгранном бое открывает настройку размеров и пропусков текущего круга. Размеры вводятся через +. Сыгранные бои и их исходный счёт сохраняются; меняются только несыгранные группы. Тот же контроль появляется при добавлении/выводе участников. При начале любого круга размеры тоже можно проверить и изменить явно.

В разделе «Вынужденные пропуски» отметьте тех, кто не сыграет этот круг. Это не нулевой счёт и не снятие: очков нет, отметка видна в результатах/полном CSV, активный состав следующего круга не меняется. Снять отметку можно, пока игрока можно вернуть в несыгранные группы. Участника уже сыгранного боя отметить пропустившим нельзя. Оба варианта сохраняются в приватной истории и резервной копии. Если пропустили все, круг завершится без вымышленных боёв/очков. Автоматической компенсации нет.

Полный CSV имеет колонку «Статус»: у пропуска пустой счёт. В фиксированный рейтинговый Data экспортируются только реально сыгранные бои до четырёх игроков; бо́льшие бои явно перечислены как не включённые и доступны полностью в CSV. Несохранённый ввод привязан к ID игроков в бою; после чужого перераспределения старые поля очищаются, чтобы не приписать результат другому человеку.

## Размер финалов и полный экспорт

В каждом финале можно выбрать от 1 участника до доступного активного состава (не больше 40 уникальных финалистов суммарно); малый финал необязателен. Один игрок не может участвовать в обоих. Места рассчитываются автоматически по убыванию счёта. Равный счёт даёт среднее место, как в предварительных играх: например1, 2,5, 2,5, 4. На сервер отправляется только счёт; присланные вручную места не могут изменить расчёт. Нумерация малого финала идёт после фактического числа участников грандфинала: 5+3 даёт диапазоны1–5 и6–8, 3+5 —1–3 и4–8. Ранее записанные ручные места сохраняются при просмотре и восстановлении; при подтверждённом исправлении счёта этого боя они пересчитываются автоматически. Предыдущие значения остаются в истории. Старые финалы также сохраняют свои прежние диапазоны нумерации. Уже назначенный финал можно отменить в настройках и выбрать состав заново.

«Все бои · CSV» выгружает всех игроков, исходный счёт, круг/бой и место в финале. Это обычная таблица для отдельного листа Google Таблиц. Формат рейтингового листа Data рассчитан на четыре места: бои больше четырёх участников туда не включаются, о чём окно экспорта сообщает явно. Предварительные и подходящие финальные бои экспортируются прежними блоками6×4; большой финал полностью остаётся в CSV и резервной копии. Структура Google Sheet и его формулы не меняются.

## Исправления после старта и пример экспорта

Кнопка ↻ доступна рядом с боями каждого из трёх кругов: первый круг перемешивается случайно, второй/третий пересчитываются по тем же швейцарским правилам из очков и повторных встреч предыдущих кругов. Состав конкретного круга, размеры боёв и ID сохраняются. Если швейцарский расчёт даёт те же группы, окно сообщает об этом, сохраняя весь счёт и следующие игры. Иначе перед подтверждением показано, сколько результатов текущего круга сбросится и какие следующие круги/финалы отменятся; более ранние круги сохраняются, прежние данные остаются в истории. При неизменных исходных данных швейцарская жеребьёвка детерминирована — кнопка не ищет произвольные случайные варианты. Для ручной поправки остаётся обмен игроков. В одном бою первого круга меняется только порядок мест.

На вкладке «Игроки» можно добавить, вывести или вернуть участника. Окно предлагает применить изменение сейчас (пересобрать только несыгранные бои текущего круга) или со следующего круга. Сыгранные бои и очки остаются; выведенный участник сохраняет имя/ID и исторические результаты. Новичок не получает очков за пропущенные бои. Для несыгранных боёв можно явно задать размеры через +: например, после добавления девятого игрока сохранить сыгранный бой из четырёх, а оставшихся пятерых разделить на3+2 либо оставить один бой из5. В каждом бою от2 до40 игроков; сумма должна совпадать с оставшимся составом. Обычная автоматическая разбивка остаётся3/4; нестандартные размеры выбираются перед подтверждением, формула очков остаётся прежней. Бой из одного игрока не создаётся. Не более 40 игроков в круге и 120 разных за три круга. Для изменения состава после назначения финалов сначала отмените финалы; завершённый или архивный турнир нужно открыть для редактирования.

«Поменять игроков в боях» работает и после записи счёта: перед подтверждением показан сброс только затронутых боёв и зависимых следующих кругов/финалов. Исправить старый счёт можно карандашом на карточке боя с тем же предупреждением. Остальные результаты этого круга сохраняются. При смене делителя после создания следующих кругов сохраняется исходный счёт первого круга, а зависимые круги и финалы отменяются после подтверждения. Отменённые данные остаются в приватном журнале.

В окне экспорта раскройте «Пример для Google Таблиц»: показаны первые шесть строк реального экспорта или вымышленный образец, если ещё нет сыгранных боёв. Отдельный файл `/export-example.tsv` содержит вымышленный бой для пробной вставки. Пример с 1000/700/700/0 показывает ничью и нулевой счёт; экспорт в Data всегда передаёт исходные значения, независимо от делителя. Образец не следует добавлять в настоящий рейтинг.

## Доступ без аккаунтов

`src/access.mjs` выдаёт случайные 256-битные секреты. Основной cookie — `__Host-svoyak-owner`, Secure, HttpOnly, SameSite=Strict, Path=/, срок до года. На сервере хранятся только хеши сессий и отдельного ключа управления каждого турнира. Таблица `tournament_owner_sessions` связывает конкретный браузер только с теми турнирами, которыми он вправе управлять. Знание публичного ID/URL, подмена полей владельца или наличие доступа к другому турниру не дают прав на изменение.

Приватная ссылка использует фрагмент `#manage=…`, который не передаётся в HTTP URL или Referer. Приложение немедленно убирает его из адресной строки и просит явное подтверждение перед обменом на HttpOnly cookie. Предпросмотр ссылки не выполняет обмен и не расходует ключ. После перезагрузки сам ключ не хранится в JavaScript-хранилищах; управление продолжает работать через cookie. Если нужно заново сохранить утраченную ссылку, владелец может явно создать новую: прежний ключ и доступ других браузеров к этому турниру будут отозваны.

Публичный ответ содержит только название и дату турнира, имена игроков, бои/счёт, финальные места и производную таблицу. В нём нет места проведения/заметок, истории, случайных seed, внутренних ревизий, cookie, хешей или полных резервных копий. Списка всех публичных турниров нет: `/api/tournaments` показывает только турниры текущего браузера. Общая документация требует действующей сессии управления; LICENSE/NOTICE и безопасные UI/домен-ресурсы доступны публично.

Резервная копия не содержит ключей и не переносит права управления. Восстановление создаёт отдельный турнир с новым приватным ключом и разрешено только браузеру, уже управляющему исходным турниром. Для другого устройства сначала откройте сохранённую приватную ссылку. Если исходной записи больше нет или потеряны и cookies, и приватная ссылка, автоматического восстановления прав нет.

Старые записи, созданные до введения владения, сохраняются с пустым хешем и не могут быть присвоены первым посетителем. Они не публикуются и не редактируются без отдельного проверенного решения о переносе. При проверке живой базы перед этой версией такими записями были только три архивных синтетических QA-турнира.

## Локальный запуск

Node.js 22.13+ (рекомендуется 24), Git и современный браузер. Установка npm-зависимостей не требуется.

```sh
npm run build
npm test
npm run dev
```

Откройте напечатанный loopback URL. `.local/tournaments.db` содержит локальную SQLite-базу; каталог исключён из Git. Сохраните его для продолжения после перезапуска. В локальном HTTP-адаптере используется отдельный HttpOnly cookie `svoyak-dev-owner` без Secure; production Worker всегда использует защищённый `__Host-` cookie. Данных/сессий между локальной и опубликованной базой нет.

## Архитектура и размещение

Sites использует Cloudflare Workers и D1 (SQLite), поэтому предпочтённый в исходном задании .NET/Blazor заменён на небольшое приложение из ES-модулей без npm-зависимостей. `src/domain.mjs` содержит правила книги и явно описанные пользовательские расширения; `src/access.mjs` — права конкретного турнира; `src/worker.mjs` — API/сохранение; `public/` — интерфейс. Сборка встраивает UI и документацию в один Worker. Исходная миграция `0000_tournaments.sql` неизменна; `0001_tournament_ownership.sql` добавляет nullable-хеш и таблицу сессий без автоматической передачи старых записей.

Все записи ревизии выполняются условным UPDATE; создание/выдача прав и замена ключа — транзакционным D1 batch. Схема создаётся только миграциями, не в production-запросах. Проверяются источник JSON-запросов и права каждого изменения/backup/restore/rollback. Секреты не попадают в публичный JSON, журнал или резервные копии. В коде/браузере нет общего административного токена Sites.

В этой среде отсутствовали документированные Sites bootstrap/source helper executables и исходники Vinext starter. Используются совместимый автономный Worker-артефакт и обычный аутентифицированный Git. `.openai/hosting.json` сохраняет идентичность Site и D1 binding `DB`. Публичный доступ допускается только после проверки серверных ограничений. Новые или заменённые служебные credentials требуют отдельного разрешения, когда это ограничение задано в чате.

## Правила и ограничения

Очки за бой = `4 − среднее место + счёт / делитель`. По умолчанию делитель 100 (точное соответствие книге); в настройках можно указать любое целое от 1 до 10000, например 200 для двухсотников. Счёт хранится в целых сотых; для произвольного делителя равенство очков и жеребьёвка сравниваются по целым общим числителям без округления. На экране очки округлены до двух знаков, в итоговой CSV — до шести; внутренний расчёт точнее отображения. При ничьей место усредняется. Жеребьёвка 2/3 круга минимизирует сумму расстояний с конечными штрафами 1000/2000 за предыдущие встречи и поправкой номера регистрации; это не запрет повторов и не обычная библиотечная Swiss-парность. Первый круг случаен, seed сохранён.

Excel/VBA не исполнялись: эталоны — независимый перевод идентифицированных формул с точной рациональной арифметикой. Отличия: другой генератор случайной первой жеребьёвки, максимум два знака счёта, атомарный полный бой и строгая проверка переходов/исправлений. Поздняя регистрация/снятие и свой делитель — явно запрошенные расширения поверх книги. Автоматические пропуски, компенсационные очки за пропущенные игры, квалификация финалистов и иные форматы не добавлены.

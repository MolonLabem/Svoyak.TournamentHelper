## Согласованный снимок и сверка

Новая схема получена без дублирования ресурсов. Перед финальным снимком Sites применил `0004_freeze_sites_source.sql`: шесть BEFORE-триггеров запрещают INSERT/UPDATE/DELETE обеих таблиц, включая запросы старых версий Worker. Экспорт проверял наличие всех шести триггеров. Поэтому ни во время чтения, ни после снимка исходные турниры и сессии не могли изменяться.

Временный server-only endpoint принимал HMAC-SHA-256 подпись точных метода, пути, timestamp и тела запроса. Секрет хранился в runtime secrets и памяти оператора, имел срок действия; допустимое окно timestamp — 60 секунд. Никаких ключей в query, публичного дампа, ослабления доступа организаторов или произвольного SQL. Каждая строка получена целиком через D1 binding; обрезанный просмотрщик Sites не использовался для импорта.

## Окончательное развёртывание

`npm run build:cloudflare` создаёт `dist/cloudflare/{metadata.json,cloudflare-entry.mjs,app.mjs}`. `deploy/cloudflare-upload.json` — metadata multipart Workers API, не конфигурация Wrangler/cf. Публикация: PUT `/accounts/{account_id}/workers/scripts/svoyak` с metadata и двумя ES modules. Не применять Sites-миграцию 0004 к назначению. Точное `SVOYAK_MIGRATION_STATUS=ready` включает приложение; иное/отсутствующее значение закрывает его.

`npm run build:sites` создаёт постоянную страницу перехода без обращения к D1. Архив Sites содержит `.openai/hosting.json`, `dist/server/index.js`, `drizzle/`; он собирается из точного pushed Sites-коммита. Сохранить версию через Sites, затем опубликовать, сохраняя audience public. Базовая `npm run build` по-прежнему собирает приложение для локальной разработки; для старого хостинга использовать именно `build:sites`.

На старом адресе API и любые записи возвращают 410 и никогда не пересылают POST-тела. Ссылка на турнир сохраняет ID. Приватный fragment сразу убирается из адресной строки и остаётся только в памяти страницы. Только кнопка «Перейти и восстановить управление» переносит его на фиксированный новый hostname, где приложение снова требует явного подтверждения. Ссылка «Открыть только результаты» не передаёт ключ. Старые cookies не переносятся между hostname; сохранённые приватные ссылки остаются пригодны для восстановления. Для просмотра и восстановления используются прежние ID и хеши, без новых владельцев.

Временные экспорт/import endpoints, модуль, доступ к pending-приложению и упаковщик переноса удалены из окончательных исходников и артефактов. После публикации удалить `SVOYAK_MIGRATION_SECRET` и `SVOYAK_MIGRATION_EXPIRES` из Sites и Cloudflare runtime. Шесть триггеров оставить как постоянную защиту исходного архива, чтобы случайная публикация старого Worker не разрешила запись.

## Откат

1. До включения Cloudflare: держать назначение `pending`. Для возврата записи в Sites добавить **новую** миграцию, удаляющую только шесть `svoyak_frozen_*` триггеров, и опубликовать исходное приложение. Не редактировать применённую 0004. Публикация v26 сама по себе не снимает защиту БД.
2. После включения Cloudflare и возможности новых записей: сначала закрыть назначение (`pending`) и поставить блокировку записи на уровне D1, дождаться прекращения изменений. Получить новый полный приватный снимок Cloudflare, сверить его и выполнить согласованный обратный перенос всех полей. Исходный снимок Sites уже нельзя считать актуальным.
3. Только после обратной сверки и при закрытом Cloudflare снять блокировку исходной D1 новой миграцией и включить Sites. Никогда не держать две независимо записываемые копии. Старую D1 не удалять.
